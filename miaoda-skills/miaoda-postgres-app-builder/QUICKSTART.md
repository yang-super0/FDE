# 开工前速查卡（QUICKSTART）

> 花 2 分钟全部打勾，再发第一条开发指令。任何一项没打勾，开工后大概率会返工。

## 一、需求确认

- [ ] 我已经清楚这个应用是给谁用的（角色）、解决什么问题
- [ ] 我已经列出了所有页面（页面清单），每个页面的类型和数据来源明确
- [ ] 我已经列出了所有数据表（数据表清单），每张表承载什么实体
- [ ] 我已经画了实体关系图（ER 图），表之间的 1:1 / 1:N / N:N 关系清晰
- [ ] 我已经列出了 AI 功能（如果有），每个的输入输出明确
- [ ] 三张清单 + ER 图已经和用户确认过，没有遗漏

## 二、技术选型确认

- [ ] 我确认这个应用需要高性能 / 复杂查询 / 大数据量，所以选 PostgreSQL 而不是多维表格
- [ ] 我不需要多人在线协作编辑数据（如果需要，应该选多维表格）
- [ ] 我了解 PostgreSQL 的基本概念（表、字段、索引、事务、JOIN）

## 三、数据库设计准备

- [ ] 每张表的字段已经设计好，字段名用英文小写下划线（如 `order_no`、`customer_id`）
- [ ] 金额字段用 `NUMERIC(12,2)`，不是 FLOAT
- [ ] 时间字段用 `TIMESTAMPTZ`，不是 TIMESTAMP
- [ ] 所有表都有 `id`（主键）、`created_at`、`updated_at`
- [ ] 需要软删除的表有 `deleted_at` 字段
- [ ] 外键关系已经明确，关联字段命名为 `xxx_id`
- [ ] 凡是 WHERE / JOIN / ORDER BY 用到的字段，都计划建索引
- [ ] 已经准备了测试数据（每表 20~50 条，含边界值）

## 四、妙搭环境准备

- [ ] 我能访问 https://miaoda.feishu.cn
- [ ] 我知道要创建「完整应用」（不是仅前端页面）
- [ ] 我了解妙搭内置 PostgreSQL 是 Serverless 版，支持分支和 Time Travel
- [ ] 如果需要 AI 能力，我已经有对应的 API Key 或知道如何配置

## 五、开发纪律确认

- [ ] 我承诺一次只让 AI 开发一个模块，不一次性生成全部
- [ ] 我承诺每个模块开发后立即在预览自测，通过后再做下一个
- [ ] 我承诺发布后到线上正式地址做冒烟测试，不信预览
- [ ] 我承诺慢查询先 EXPLAIN ANALYZE，不凭感觉优化
- [ ] 我承诺所有用户输入用参数化查询，不拼接 SQL
