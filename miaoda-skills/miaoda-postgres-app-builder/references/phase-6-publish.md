# 阶段6：发布上线

## 目标

安全发布并保证迭代质量，发布后线上功能正常、数据正确。

## 6.1 发布前检查

发布前逐项确认：

- [ ] 阶段5测试全部通过，无遗留严重问题
- [ ] 所有模块功能完整，无半成品页面
- [ ] 数据库表结构最终版已确认，索引齐全
- [ ] 测试数据已清理（或标记为测试数据）
- [ ] 生产环境需要的初始数据已录入（如管理员账号、基础字典数据）
- [ ] 环境变量已配置为生产值（不是测试值）
- [ ] 数据库分支已合并到 main（如用了分支开发）
- [ ] 已备份当前生产数据（或确认 Time Travel 可用）
- [ ] 发布回滚方案已准备（出问题能快速回退）

## 6.2 数据库 Schema 变更发布

如果发布涉及表结构变更（加字段、加索引、改类型），必须谨慎：

### 变更原则

1. **先在开发分支验证**：不要直接在生产库改
2. **向后兼容**：新字段允许 NULL 或有默认值，旧代码不会因为新字段报错
3. **加索引用 CONCURRENTLY**：避免锁表
   ```sql
   CREATE INDEX CONCURRENTLY idx_orders_customer_id ON orders(customer_id);
   ```
4. **大表加字段**：先加允许 NULL 的字段，再分批回填数据，最后加 NOT NULL 约束
5. **不要删字段**：先废弃，确认没人用了再删

### 变更流程

1. 在开发数据库分支执行变更
2. 验证应用正常
3. 用 Schema Diff 对比开发和生产的差异
4. 生成迁移脚本
5. 在生产执行迁移（低峰期）
6. 验证生产数据和应用正常
7. 出问题用 Time Travel 回退或执行回滚脚本

## 6.3 执行发布

1. 在妙搭后台点击「发布」
2. **发布是异步过程**，不要点完就不管，要轮询等待发布结果
3. 等待发布状态变为「发布成功」
4. 如果发布失败，看错误日志，修复后重新发布

## 6.4 发布后冒烟测试（每次发布必做）

发布成功后，立即到**线上正式地址**（不是编辑器预览）做冒烟测试：

### 基础冒烟（3 项）

1. **打开页面** → 正常显示，无白屏无报错
2. **新增一条测试记录** → 成功（返回 201，列表能看到）
3. **删除测试记录** → 成功（软删除，列表不再显示）

### 数据库确认

```sql
-- 确认新增的数据在数据库里
SELECT * FROM orders ORDER BY id DESC LIMIT 3;

-- 确认删除是软删除
SELECT id, deleted_at FROM orders WHERE id = 刚才删除的ID;
```

### 关键功能冒烟

- [ ] 列表查询正常（分页、筛选）
- [ ] 详情页正常（关联数据正确）
- [ ] 统计仪表盘数据正确
- [ ] 搜索功能正常
- [ ] AI 能力正常（如有）：正常输入 + 边界输入各一次

### 性能确认

- [ ] 关键接口响应时间 < 500ms（浏览器 F12 看）
- [ ] 无慢查询（看数据库慢查询日志）
- [ ] 数据库连接数正常，无耗尽

## 6.5 发布后监控

发布后 1 小时内重点关注：

- **错误日志**：应用有无 500 错误
- **数据库**：连接数、慢查询、锁等待
- **用户反馈**：有没有用户报告问题
- **性能**：页面加载时间、接口响应时间

如果发现严重问题，立即回滚：
1. 应用回滚到上一个版本
2. 数据库用 Time Travel 回退到发布前的状态（如果有数据变更）
3. 确认回滚后功能正常

## 6.6 交付

发布稳定后，向用户交付：

1. **线上访问地址**
2. **管理员账号**（如创建了）
3. **使用说明**（简要）
4. **已知限制**（如不支持什么、有什么边界）
5. **后续迭代规则**：
   - 小改动直接在开发分支做，测试后发布
   - 大功能新建 feature 分支
   - 改表结构前先备份/建分支
   - 每次发布做冒烟测试

## 完成标准

- [ ] 发布前检查全部通过
- [ ] 数据库 Schema 变更已安全执行（如有）
- [ ] 发布成功，状态明确
- [ ] 线上冒烟测试通过（打开+新增+删除+关键功能）
- [ ] 数据库确认数据正确
- [ ] 性能达标
- [ ] 发布后 1 小时无严重问题
- [ ] 已向用户交付地址和使用说明
