# 开工前速查卡（Pre-flight）

> 用法：给妙打发**第一条指令前**，花 2 分钟过一遍，全部打勾再开工。只放最致命的前置动作，原理看 `SKILL.md`，细节看 `references/`。

## 一、方向对齐（没对齐不开工）
- [ ] **三张清单已列**：页面清单 / 数据表清单 / AI 功能清单，每条都能对应到原始需求
- [ ] **清单已经用户确认**（防止做偏，阶段1门禁）
- [ ] **每张表都标了"给谁用"**：被哪个页面 / 哪个 AI 用到，没有孤立表（建表≠连通）
- [ ] **每条核心业务流程已按最长路径推演**：每步读/写哪些表，「业务动作×写入表」矩阵已列，驳回/重复路径想过（防上线后流程断链）

## 二、数据核验（别凭假设）
- [ ] 已**回读线上真实字段**：字段名 / 类型 / 单选枚举，没把单选当文本，空列已标注忽略
- [ ] Base Token、各 table_id 已记录
- [ ] 涉及写操作：飞书自建应用凭证（App ID/Secret）已配置，否则发布后写必报 `kctx is nil`

## 三、节奏规划（别一次性全做）
- [ ] 已排模块开发顺序：数据层/字段适配 → 主表列表详情 → 其余表 → 搜索 → AI 能力 → 聚合收尾
- [ ] **本次只做第一个模块**，不一次性生成全部页面
- [ ] 第一条指令写清四件事：本次范围 / 数据源(真实字段) / 本次不做什么 / 做完先自测、先别发布

## 四、涉及 AI 能力才看（四层兜底）
- [ ] AI 候选**合并所有相关表**（防漏表导致返回空）
- [ ] AI 入参空值有兜底（不传空字符串）；提示词写明"禁止空返回、补足条数、不杜撰、固定公司主体"
- [ ] AI 返回空时前端有规则结果兜底，不出现空态/白屏
- 详见 `references/ai-component-patterns.md`

## 五、验收底线（交付前）
- [ ] 边界值都计划测：分类"全部" / 空输入 / 无匹配 / AI 返回空
- [ ] 下载接现取临时下载链接（24小时时效、勿缓存）、详情显示真实正文，不做只能看不能用的 UI 壳子
- [ ] 到**线上正式地址**实测 + 抓关键接口入参/出参；不信"编译通过"和 AI 自述"自查通过"
- [ ] **全链路回归**：每条核心业务流程（按最长路径）端到端真实走一遍，每步联动写入落库、下游 KPI/图表与表格数据对数一致；重复操作一次验幂等

---

### 五条红线（一句话版）
1. 凡字段必核验　2. 建表≠连通（读+写）　3. 确定性归规则、不确定才归 AI　4. 编译通过≠功能正确、AI 自查≠真通过　5. 每条流程先推演（最长路径）、全链路回归收尾

### 第一条指令万能骨架
> 【本次范围】只做「模块X」，不改其他模块。【数据源】只用「表/插件」，字段(名/类型/枚举)：……。【要实现】1…2…。【本次不做】……。【完成后先别发布】列改动文件，预览自测正常+边界+数据来源，通过后报告等我确认。

> 模块开发模板、自测、回归保护的完整提示词见 `references/phase-5-development.md` 第 5.2 节。
