# 阶段2：多维表格设计

## 目标
设计稳定、可扩展的表结构，避免后期改字段。

## 执行步骤

### 2.1 表拆分原则
- 一表一实体：订单表、客户表、商品表、收款表、售后表分开
- 用自增编号作为业务主键（如 SO202601001）
- 表间关系用关联字段（Link）建立
- 每张表都要能说清"将来被哪个页面/AI 用到"，不建无消费方的孤立表（见 `data-lineage.md`）

### 2.2 字段类型选择矩阵

| 业务需求 | 推荐类型 | 写入格式 | 读取格式 | 风险等级 |
|---|---|---|---|---|
| 名称/描述 | 文本 | string | string | 低 |
| 金额/数量 | 数字 | number | number | 低（注意NaN） |
| 日期 | 日期 | 毫秒时间戳 | 毫秒时间戳 | 中（前端需转换） |
| 状态/等级/行业/分类 | 单选 | 选项文本 | 选项文本 | 中（易被误当文本，选项须一致） |
| 多标签 | 多选 | string[] | string[] | 中 |
| 负责人 | 人员 | [user_id数字] | 对象数组 | 高（需通讯录权限） |
| 订单→客户 | 关联 | [{"id":"rec_xxx"}] | link_record_ids | 高（需标题回填） |
| 凭证图片 | 附件 | file_token[] | 对象数组 | 高（需先上传） |
| 金额合计 | 公式 | 只读 | 计算结果 | 中（不可写入） |

### 2.3 小白第一版建议
- 人员字段 → 先用文本存人名
- 关联字段 → 先用文本存名称，熟练后再改
- 附件字段 → 第一版不做
- 公式字段 → 可用，但别做关键计算

### 2.4 必须记录的配置信息
```
Base Token (app_token): 从多维表格URL获取
各表 table_id: 表名旁...→复制表ID
各字段名+类型+单选枚举: 以回读到的线上真实定义为准
```

### 2.5 测试数据
每张表录入5-10条测试数据，覆盖各种状态和字段组合。

### 2.6 建表后回读真实字段（强制）
表建好、数据录完后，**回读一次线上真实字段定义并记录**，作为后续代码的唯一依据：
- 真实字段名（可能与设计用词不同）
- 真实字段类型（状态/行业/等级/分类这类常被建成**单选**，不要当文本）
- 单选/多选的全部枚举选项文本（写入需逐字一致）
- 标注空列/废列，后续忽略

> 目的：防止凭字段名想当然导致读取为空（坑11）。字段适配细节见 `field-adaptation.md`。
> 多张表时，在此同步登记每张表"将被哪个页面/AI 用到"，见 `data-lineage.md`。

## 完成标准
- [ ] 所有表已创建，字段类型正确
- [ ] Base Token 和各表 table_id 已记录
- [ ] **已回读真实字段定义（名/类型/枚举）并与设计核对，空列已标注**
- [ ] **多表时已初步登记每张表的消费方**
- [ ] 测试数据已录入
- [ ] 高风险字段已按建议降级处理
