# 阶段7：发布上线与运维

## 目标
安全发布并保证后续迭代质量。

## 7.1 发布前检查
- [ ] `.env` 凭证正确配置
- [ ] 阶段5各模块自测、阶段6全量与边界测试均通过
- [ ] 代码已提交
- [ ] **注意：无编译错误只是底线，不代表功能正确**（坑17），功能以实测为准
- [ ] 重要数据已备份

## 7.2 执行发布
1. 点妙搭右上角「发布」
2. 选择发布范围：
   - 互联网：公开链接，任何人可访问
   - 企业内：仅企业内用户
3. **发布是异步过程，需轮询等待，直到出现明确的"发布成功"状态**（通常1-3分钟，期间不要重复触发或判定完成）
4. 复制**线上正式地址**（feishuapp.com 域名的应用地址），不要用编辑器内置预览地址当交付

## 7.3 发布后冒烟测试（必做，在线上正式地址）
发布后立即在正式环境验证，编辑器预览通过不能替代：
1. 打开页面 → 正常显示
2. 新增一条测试记录 → 成功（201，非500）
3. 删除测试记录 → 成功
4. **关键搜索/AI 能力**：正常输入一次 + 边界输入（空/无匹配）一次，确认有结果、不报错、不白屏
5. **抓 1 个关键接口**：入参候选完整、出参非空
6. **跨表联动验证（如有联动写入）**：触发一次联动业务动作（如标记已打款→自动记流水），核对联动表新增记录、下游 KPI/图表变化；验证后清理测试数据

上述通过才算发布完成。写操作冒烟细节见 `phase-6-testing.md`。

## 7.4 运维迭代
- 后端开启请求/响应日志（`LOG_REQUEST_BODY=true`）
- 新需求通过妙搭AI输入框描述，AI自动修改
- ⚠️ **每次迭代继续按阶段5的"单模块闭环"：一次改一个模块、自测、回归已测模块，再发布**
- ⚠️ 每次修改后重新发布，都要在线上地址重做冒烟测试
- 改了多维表格字段后：先回读真实字段定义，再让 AI 同步适配层，最后回归相关页面
- 定期导出多维表格数据备份

## 7.5 迭代原则
- 小步快跑：一次只做一个模块，测通发布后再加下一个
- 不要一次让AI做十几个页面（坑18）
- 保留测试账号和测试数据，不要用真实数据测试删除
- 不以 AI 自述的"自查通过"作为完成标准，以本人在线上地址的实测为准（坑17）

## 完成标准
- [ ] 已等到明确"发布成功"
- [ ] 已在线上正式地址（非编辑器预览）完成冒烟
- [ ] 写操作冒烟通过，关键 AI/搜索能力正常+边界各一次
- [ ] 跨表联动冒烟通过（如有）：联动写入落库且下游 KPI/图表同步变化
- [ ] 发布地址已交付用户
- [ ] 运维和迭代规则已告知用户
